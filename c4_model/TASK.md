# C4 Model

## Цель

Научиться документировать архитектуру программных систем с помощью C4 Model
и строить понятные диаграммы уровней Context и Container.

## План изучения

### 1. Основные понятия

- Разобрать назначение C4 Model и её четыре уровня: Context, Container,
  Component, Code.
- Понять, для какой аудитории предназначен каждый уровень.
- Изучить базовые элементы: Person, Software System, Container, Component.
- Отличать C4 от UML и понимать, когда их сочетать.

### 2. Нотация и правила

- Подписывать каждый элемент: название, тип, технология, ответственность.
- Подписывать каждую связь: назначение и протокол.
- Добавлять заголовок, легенду и область диаграммы (scope).
- Избегать неоднозначных стрелок и сокращений без расшифровки.

### 3. Диаграмма Context (уровень 1)

- Показать систему как единый блок.
- Выделить пользователей и роли.
- Отразить внешние системы и интеграции с ними.
- Проверить диаграмму на понятность для нетехнической аудитории.

### 4. Диаграмма Container (уровень 2)

- Выделить разворачиваемые единицы: веб-приложения, API, базы данных,
  очереди, кеши, фоновые обработчики.
- Указать технологии каждого контейнера.
- Отразить протоколы взаимодействия: HTTP, gRPC, AMQP, SQL.
- Показать границы системы и связи с внешними системами.

### 5. Диаграммы Component и Code

- Разобрать декомпозицию контейнера на компоненты.
- Понять, когда уровень Code не нужен и лучше генерируется из кода.
- Построить диаграмму Component для одного ключевого контейнера.
- Определить, какие уровни поддерживать в актуальном состоянии.

### 6. Дополнительные диаграммы

- Изучить System Landscape для набора систем организации.
- Разобрать Dynamic diagram для описания конкретного сценария.
- Изучить Deployment diagram для отображения инфраструктуры.
- Связать дополнительные диаграммы с основными уровнями.

### 7. Инструменты: диаграммы как код

- Изучить Structurizr DSL.
- Изучить C4-PlantUML и Mermaid C4.
- Хранить диаграммы в репозитории рядом с кодом и документацией.
- Генерировать изображения в CI и проверять синтаксис.

### 8. Поддержка актуальности

- Определить владельцев диаграмм и порядок обновления.
- Обновлять диаграммы в рамках изменений архитектуры.
- Использовать одну модель для нескольких представлений.
- Проводить ревью диаграмм вместе с архитектурными решениями.

## Практический проект

Построить диаграммы C4 для системы заказов:

- диаграмма Context: покупатели, операторы, система заказов, платёжный
  шлюз, служба доставки, система уведомлений;
- диаграмма Container: веб-клиент, API Gateway, сервисы заказов, оплаты и
  склада, базы данных, брокер сообщений, кеш;
- для каждого элемента указаны название, тип, технология и ответственность;
- для каждой связи указаны назначение и протокол;
- диаграммы описаны кодом (Structurizr DSL, C4-PlantUML или Mermaid) и
  сохранены в репозитории вместе со сгенерированными изображениями.

## Критерии завершения

- Диаграмма Context понятна без устных пояснений, в том числе нетехнической
  аудитории.
- Диаграмма Container отражает все разворачиваемые единицы, хранилища и
  протоколы.
- У каждой диаграммы есть заголовок, легенда и подписи всех элементов и связей.
- Диаграммы хранятся как код и воспроизводимо генерируются в изображения.
