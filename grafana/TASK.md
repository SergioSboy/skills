

# Grafana Dashboards





## Цель



Освоить полный цикл наблюдаемости Ruby-приложения: сбор технических и

бизнес-метрик, хранение в Prometheus, визуализация в Grafana и настройка

алертов.



## План изучения



### 1. Prometheus



- Изучить архитектуру Prometheus, pull-модель и service discovery.

- Разобрать типы метрик и модель данных: metric name, labels и time series.

- Понять влияние cardinality и правила выбора labels.



### 2. Экспортер на Ruby



- Подключить `prometheus-client`.

- Запустить Rack endpoint `/metrics`.

- Проверить формат экспозиции и сбор метрик Prometheus.



### 3. Базовые метрики



- Добавить `Counter` для количества запросов.

- Добавить `Histogram` для latency.

- Добавить `Gauge` для активных соединений.

- Проверить корректность изменения метрик под нагрузкой.



### 4. Инструментация Rails



- Добавить Rack middleware для сбора HTTP-метрик.

- Использовать labels для метода, нормализованного endpoint и статуса ответа.

- Исключить чувствительные данные и labels с высокой cardinality.



### 5. Инструментация Sidekiq



- Собирать количество выполненных и завершившихся ошибкой задач.

- Измерять время выполнения.

- Контролировать длину очереди, задержку и количество повторных попыток.



### 6. Инструментация базы данных



- Собирать количество и длительность запросов Active Record.

- Выделять медленные запросы.

- Контролировать размер и занятость пула соединений.



### 7. Бизнес-метрики



- Добавить метрики регистраций, платежей и активных пользователей.

- Использовать ограниченные labels, например `status` и `plan`.

- Описать бизнес-смысл и владельца каждой метрики.



### 8. Настройка Prometheus



- Подготовить `prometheus.yml` с Ruby-приложением в targets.

- Настроить и обосновать scrape interval.

- Проверить состояние target и выполнение PromQL-запросов.



### 9. Дашборд Grafana



- Подключить Prometheus как data source.

- Создать панели доступности, RPS, error rate и latency.

- Использовать `rate()` и `histogram_quantile()`.

- Добавить переменные, единицы измерения и понятные легенды.



### 10. Алерты



- Настроить правила для высокого error rate и превышения latency.

- Подключить Prometheus Alertmanager.

- Добавить `for`, labels, annotations и runbook URL.

- Проверить состояния pending, firing и resolved.



### 11. JSON как код



- Экспортировать dashboard в JSON и хранить его в репозитории.

- Убрать из JSON изменяемые вручную идентификаторы и секреты.

- Настроить доставку через provisioning, API или dashboard grabber.

- Проверить воспроизводимое развёртывание на чистой Grafana.



### 12. Финальный проект



Создать полноценный дашборд для Rails, Sidekiq и PostgreSQL:



- обзор состояния сервиса;

- RED-метрики HTTP;

- очереди и ошибки фоновых задач;

- запросы и пул соединений PostgreSQL;

- ключевые бизнес-метрики;

- рабочие алерты и ссылки на runbook.



## Артефакты



- Инструментированное Ruby/Rails-приложение.

- Конфигурации Prometheus и Alertmanager.

- Dashboard JSON и инструкция по развёртыванию.

- Набор PromQL-запросов.

- Скриншоты или запись проверки алертов.



## Критерии завершения



- Все компоненты финального проекта разворачиваются воспроизводимо.

- Метрики не содержат секретов и неконтролируемых labels.

- Дашборд позволяет определить источник типового сбоя.

- Алерты проверены искусственно созданной нагрузкой или ошибкой.
