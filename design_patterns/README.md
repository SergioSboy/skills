# Паттерны проектирования

## Цель

Научиться распознавать типовые проблемы проектирования и решать их с помощью
паттернов: понимать назначение каждого паттерна, его компромиссы и уметь
обоснованно выбирать паттерн или отказываться от него.

## План изучения

### 1. Основные понятия

- Разобрать, что такое паттерн проектирования и из каких частей он
  описывается: проблема, решение, последствия.
- Изучить классификацию GoF: порождающие, структурные и поведенческие
  паттерны.
- Понять разницу между паттернами проектирования, архитектурными паттернами
  и идиомами языка.
- Разобрать антипаттерны и риск избыточного применения паттернов.

### 2. Принципы объектно-ориентированного проектирования

- Изучить принципы SOLID на примерах нарушений и исправлений.
- Разобрать принципы «программируй на уровне интерфейсов» и «предпочитай
  композицию наследованию».
- Изучить DRY, KISS, YAGNI и закон Деметры.
- Разобрать понятия связанности (coupling) и связности (cohesion).

### 3. Порождающие паттерны

- Factory Method и Abstract Factory.
- Builder.
- Prototype.
- Singleton и причины, по которым его считают антипаттерном; альтернатива
  через внедрение зависимостей.

### 4. Структурные паттерны

- Adapter для интеграции с внешними API.
- Decorator для добавления поведения без наследования.
- Facade для упрощения работы со сложной подсистемой.
- Proxy: кеширующий, защищающий, ленивый.
- Composite, Bridge и Flyweight.

### 5. Поведенческие паттерны

- Strategy для замены ветвлений по типу.
- Observer и публикация событий.
- Command, включая очереди и отмену операций.
- Template Method и его сравнение со Strategy.
- State для конечных автоматов.
- Chain of Responsibility для конвейеров обработки (middleware).
- Iterator, Mediator, Memento, Visitor — обзорно.

### 6. Паттерны корпоративных приложений

- Repository и Data Mapper в сравнении с Active Record.
- Service Object, Query Object, Form Object.
- Unit of Work и Identity Map.
- Value Object и Null Object.

### 7. Паттерны в языке и фреймворках

- Найти реализации паттернов в стандартной библиотеке и фреймворке
  проекта (например, Rack middleware как Chain of Responsibility,
  ActiveSupport::Notifications как Observer).
- Разобрать, какие паттерны упрощаются в динамических языках (duck typing,
  блоки, модули-примеси).
- Изучить идиоматичные альтернативы классическим реализациям GoF.

### 8. Выбор паттерна

- Начинать с проблемы, а не с паттерна.
- Вводить паттерн при рефакторинге, когда проблема проявилась.
- Оценивать цену паттерна: дополнительные классы, косвенность, сложность
  чтения.
- Документировать выбор паттерна в коде или в ADR.

## Практический проект

Реализовать учебный модуль расчёта и оформления заказа с применением
паттернов:

- Strategy — расчёт скидок по типу клиента вместо цепочки условий;
- Factory Method — создание способа доставки по параметрам заказа;
- Adapter — интеграция с двумя разными платёжными шлюзами через единый
  интерфейс;
- Decorator — добавление журналирования и повторов к вызовам шлюза;
- Observer — уведомление подсистем о смене статуса заказа;
- State — переходы статусов заказа с проверкой допустимости;
- для каждого паттерна описать решаемую проблему, альтернативы и
  последствия, покрыть реализацию юнит-тестами.

## Критерии завершения

- Для каждого применённого паттерна сформулирована проблема, которую он
  решает, и рассмотрена альтернатива без паттерна.
- Добавление нового типа скидки, доставки или шлюза не требует изменения
  существующего кода, кроме регистрации.
- Код модуля соответствует принципам SOLID, что подтверждено на Code Review.
- Сотрудник может объяснить различия близких паттернов: Strategy и State,
  Decorator и Proxy, Adapter и Facade.
