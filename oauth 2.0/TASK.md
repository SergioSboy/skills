

# OAuth 2.0 / OpenID Connect

## Цель

Научиться проектировать и безопасно реализовывать авторизацию OAuth 2.0 и

аутентификацию OpenID Connect для веб-приложений, API и сервисных интеграций.

## План изучения



### 1. Основные понятия



- Разобрать роли Resource Owner, Client, Authorization Server и Resource Server.

- Отличать аутентификацию от авторизации.

- Понять назначение access token, refresh token и ID token.

- Изучить scopes, claims, consent и redirect URI.



### 2. OAuth 2.0



- Разобрать Authorization Code, Client Credentials и Device Authorization Grant.

- Изучить назначение PKCE и обязательность его применения для публичных клиентов.

- Понять, почему Implicit Grant и Resource Owner Password Credentials не следует

  использовать в новых системах.

- Сравнить confidential и public clients.



### 3. OpenID Connect



- Изучить Discovery, UserInfo и стандартные OIDC scopes.

- Разобрать содержимое и назначение ID token.

- Проверять issuer, audience, подпись, срок действия и nonce.

- Понять назначение параметров `state`, `nonce` и `prompt`.



### 4. JWT и непрозрачные токены



- Разобрать структуру JWT и алгоритмы подписи.

- Изучить JWK, JWKS и ротацию ключей.

- Сравнить локальную проверку JWT с token introspection.

- Не использовать содержимое неподписанного или непроверенного токена.



### 5. Безопасность потоков



- Защититься от CSRF, authorization code interception и mix-up атак.

- Настроить точное сравнение redirect URI.

- Ограничить срок жизни токенов и права scopes.

- Реализовать безопасное хранение и ротацию client secrets.



### 6. Управление сессиями и токенами



- Реализовать обновление access token через refresh token.

- Изучить refresh token rotation и обнаружение повторного использования.

- Настроить отзыв токенов и завершение пользовательской сессии.

- Продумать повторную аутентификацию для критичных операций.



### 7. Authorization Server



- Развернуть Keycloak, Dex или другой совместимый провайдер.

- Создать realm/tenant, клиентов, пользователей, роли и scopes.

- Настроить Authorization Code Flow с PKCE.

- Проверить discovery document и JWKS endpoint.



### 8. Resource Server



- Защитить тестовое API проверкой access token.

- Валидировать подпись, issuer, audience, срок действия и scopes.

- Разделить ответы `401 Unauthorized` и `403 Forbidden`.

- Обработать ротацию ключей без остановки сервиса.



### 9. Клиентское приложение



- Реализовать вход через OIDC в тестовом веб-приложении.

- Безопасно обработать callback, `state`, `nonce` и ошибки провайдера.

- Не передавать токены в URL и журналы.

- Настроить корректный logout и очистку локальной сессии.



### 10. Диагностика и аудит



- Анализировать протокол через браузерные инструменты и безопасные тестовые

  декодеры JWT.

- Добавить аудит выдачи, обновления и отзыва токенов без записи самих токенов.

- Проверить обработку просроченного токена, неверной audience и недостаточного

  scope.

- Подготовить runbook для проблем входа и ротации ключей.



## Практический проект



Развернуть Authorization Server, клиентское приложение и защищённый API:



- вход пользователя по Authorization Code Flow с PKCE;

- проверка ID token и access token;

- разграничение доступа с помощью scopes или ролей;

- обновление и отзыв токенов;

- ротация ключей подписи;

- набор позитивных и негативных интеграционных тестов.



## Критерии завершения



- OAuth 2.0 и OpenID Connect применяются по назначению и не смешиваются.

- Все токены проверяются по подписи, issuer, audience и сроку действия.

- Поток защищён с помощью PKCE, `state` и `nonce`.

- Секреты и токены отсутствуют в URL, исходном коде и журналах.

- Отзыв токена и ротация ключей подтверждены тестами.
