# Сетевой уровень

## Зачем нужен еще один уровень?

Если мы хотим построить сеть с технологией канального уровня возникнут проблемы:

- Технологий много разных и не понятно как объдинять
- Технолоии подходят для локальных сетей но плохо для канальных

## Различия сетей

По уровню сервиса
- Без гарантии доставки (Ethernet)
- С гарантей (Wi-Fi)
- С гарантией доставки и порядка следования сообщений

По типу адресаций
- Разный размер, плоская, иерархическая
- Ethernet - MAC, Сети сотовой связи - IMEI

Широковещание:
- Поддерижвается или нет

Максимальный размер кадра (MTU)
- Ethernet - 1500, Wi-Fi - 2304

Формат кадра

## Что можно сделать на сетевом уровне чтобы согласовать различие в сетях?

Тип сервиса
- Кадры из Wi-Fi принимаются с отправкой подтверждаются а в Ethernet отправляется без подтверждений

L3 абстракция здесь помогает не зависеть от типа сервиса ей все равно по какому каналу произойдет доставка IP-пакета

Чтобы согласовать адреса на сетевом уровне
- Вводятся адреса, не зависимые от конкретных технологий
- Методы преобразования глобального адреса в локальный (ARP для TCP/IP)

L3 абстракция здесь создает уникальные IP-адреса по которым будет идти доставка на всем пути до конечного узла

Широковещание
- Пакеты отправляются всем хостам в сете по индивидуальным адресам

L3 абстракция здесь такая что бродкаст происходит на конкретный IP-адрес который слушают все участники локальной сети

## Что делать с максимальным пакетом в сетях?

Когда мы передаем данные от отправителя к получателю мы не можем заранее знать какие сети будут по пути
и какой там размер кадра. Для того чтобы согласовать размеры кадров на канальном уровне на сетевом уровне
используется "фрагментация" (fragmentation)

MTU (Maximum Transmission Unit) - характеристика канала или интерфейса. Максимальный размер полезной нагрузки
на канальном уровне

## Различия в технологиях канального уровня

Сейчас почти везде используется технология Ethernet
Wi-Fi адаптация Ethernet для беспроводной сети

## Почему нельзя строить сети только на Ethernet?

Таблица коммутации:
- Должна содержать MAC адреса всех хостов в сети
   Если для локальной сети можно это сделать, то для глобальной сети мы сталкиваемся с проблемами масштабируемости.
   Сколько хостов в Интернете? Сколько памяти нужно для хранения такой таблицы? Как быстро будет осуществлятся поиск?

Отправка пакетов на все порты:
- Передача кадров на все порты
   Если коммутатор не знает где находится хост, он отправляется кадр на все порты. Возникает проблема масштабируемосяти.
   Сколько не нужных кадров будет передаваться в Интернете?

Отсутствие дублирующих путей между коммутаторами:
- STP обнаруживает и отключает дублирующие пути
- Активный путь всегда только один

## Что делает Сетевой уровень для того чтобы обеспечить масштабируемость?

- Агрегация адресов:
   Сетевой уровень работает не с отдельными адресами, а с блоками адресов. Отдельный блок - независимая сеть.

- Запрет пересылки "мусорных" пакетов:
   Пакет отбрасывается если нельзя определить, куда его нужно доставить

- Возможность наличия нескольких путей в сети:
   Одна из основных причин создания сете с пакетной коммутацией. Допускается несколько активных путей.
   Появляется задача маршрутизации - выбора лучшего пути.

## Какие задачи решает сетевой уровень?
- Объединение сетей. Создание составной сети на основе сетей построенных на разных технологиях канального уровня.
- Маршрутизация. Поиск маршрута в такой сети где может быть несколько маршрутов в такой сети и нужно будет выбрать наилуший.
- Обеспечение качества обслуживания

## Обрудование сетевого уровня
Маршрутизатор - это устройство объединения сетей. У маршрутизатора есть несколько интерфейсов через них
к маршрутизатору подключаются сети. У каждого интерфейса у маршрутизатора есть адрес.
У интерфейсов коммутатора своих адресов нет. 

### Если есть необходимость объеденить несколько сетей
Для этого обязательно нужен маршрутизатор. Нельзя взять и подключить одну сеть к другой и передавать данные 
напрямую. 

# Маршрутизация (Routing)

Маршрутизация (routing) - поиск маршрута доставки пакета (данных) между сетями через транзитные узлы - маршрутизаторы.

Маршрутизация для каждой порции данных (пакетов) происхдоит каждый раз заново. Чтобы не возникло ошибки, если какой-то маршутизатор
выйдет из строя и заранее выбранный маршрут стал недоступным.

## Какие здесь могут быть сложности?

- Структура сети со временем может изменяться.
   Могут появлятся новые маршрутизаторы. Существующие маршрутизаторы могут выходить из строя и отключаться от сети.
   Поэтому необходимо учитывать изменения в топологии сети.

- Равномерное распределение нагрузки между каналами связи и маршрутизаторами. 
   Чтобы не перегружать и не догружать каналы связи. Это позволит более эффективно использовать пропускную спосбоность сети.

Продвижение (forwarding) - передача пакета внутри маршрутизатора в соответствии с правилами маршрутизации.

По сути это поиск маршрута для каждого пакета, который пришел на маршртизатор при этом маршрутизатор уже знает
топологию сети и знает загрузку каналов.

# Сетевой уровень в TCP/IP

## Используемые протоколы 

IP (Internet Protocol) используется для передачи данных

ICMP (Internet Control Message Protocol) используется для управления сетью

ARP (Address Resolution Protocol) используется для того чтобы по глобальному адресу сетевого уровня
определить локальный адресс по технологии канального уровня

DHCP (Dynamic Host Configuration Protocol) простокол динамической конфигурации хостов. Используется для того чтобы
автоматический размечать адреса компьютеров в составной сети

# IP-адрес

## Локальные и глобальные адреса

### Локальные адреса

Адреса в технологии канального уровня которые привязаны к технологиям канального уровня:

- MAC адрес в Ethernet
- IMEI в 4G

Такие адреса не могут использоватсяь для построения крупной составной сети, которая объединяет сети использующие разные технологии

### Глобальные адреса

Адреса сетевого уровня:

- IP-адрес

Глоабальные адреса не привязаны к технолгиям канального уровня и при помощи них можно построить такую сеть которая объединяет сети построенные на разных технологиях
канального уровня и передавать данные из этих сетей друг другу


IP-адрес применяется для уикальной идентификации компьютеров в составной сети которая может включать в себя весь мир


## Агрегация адресов

Сетевой уровень использует агрегацию адресов для получения масштабируемости работа происходит не с отдельными адресами а с подсетями

## Подсеть (IP-сеть, subnet)

Подсеть это множество компьютеров у которых старшая часть IP-адреса одинаковая

Маршрутизаторы работают с подсетями, а не с отдельными компьютерами

## Структура IP-адреса

### Старшие биты

Номер подсети

### Младшие биты

Номер хоста (компьютера в сети)

IP-адрес: 213.180.183.1
Номер подсети: 213.180.193.0
Номер хоста: 1

### Маска подсети 

Маска подсети указывает, где именно заканчивается сетевая часть и начинается хостовая.

Биты, установленные в 1, относятся к сети.

Биты, установленные в 0, относятся к хосту.

Пример:
IP-адрес: 192.168.1.10

Маска: 255.255.255.0 (в двоичном виде: 11111111.11111111.11111111.00000000)

Это означает, что первые 24 бита отданы под сеть, а последние 8 бит — под хосты.


Как можно указать маску подсети?

Дестяичное представление:
- IP-адрес: 192.168.1.10
- Маска подсети: 255.255.255.0
- Адрес подсети: 192.168.1.0

В виде префикса:
- 213.180.193.3 /24
- 213.180.193.0

Оба представления эквивалентны 
 
### CIDR (Classless Inter-Domain Routing)

CIDR заменяет традиционные классы сетей (A, B, C) префиксной записью. Префикс /N показывает количество единичных бит в маске.

## Типы IP-адресов

### Индивидуальный (unicast)

Адрес конкретного компьютера в сети

### Групповой (multicast)

Адрес который используется несколькими компьтерами


### Широковещательный (broadcast)

Адрес который используется для получения данных всеми компьтерами в сети

Формат

- В номере хоста все единицы
- IP-адрес: 213.180.193.3 /24
- Широковещательный адрес: 213.180.193.255

В IP широковещательные пакеты передаются только внутри подсети (ограниченное широковещание)
- Маршрутизаторы не передают широковещательные пакеты
- Нет возможности указать в адресе "все компьтеры в Интернете"

Ограниченное широковещание (255.255.255.255)

Направленное широковещание (192.143.12.255)


## Специальные типы адресов (IPv4)

В номере хоста нельзя исопльзовать только битовые 0 или 1

Битовые 0 в номере хоста явлется адресом подсети (192.11.11.0)

Битовые 1 в номере хоста являются широковещательным адресом (213.189.181.255)

Договоренность:
Хост с номером 1 - маршутизатор по умолчанию (шлюз) 213.12.21.1 

Служебные и частные адреса  

Private Addresses (RFC 1918): адреса для локальных сетей. Не маршрутизируются в глобальном интернете.
Могут использоваться внутри организации.

- 10.0.0.0/8 (от 10.0.0.0 до 10.255.255.255)
- 172.16.0.0/12 (от 172.16.0.0 до 172.31.255.255)
- 192.168.0.0/16 (от 192.168.0.0 до 192.168.255.255)

Loopback: 127.0.0.0/8 (обычно 127.0.0.1 localhost). Виртуальный интерфейс хоста, служащий для обращения программы к самой себе без отправки трафика в физическую сеть.

Link-Local (APIPA): 169.254.0.0/16. Автоматически назначаются операционной системой, если не удалось получить IP через DHCP и нет статических настроек.

Default Route / Any: 0.0.0.0/0. Обозначает "любая сеть".

## Основы IPv6

IPv6 разработан для замены IPv4 и решает проблему истощения адресного пространства.

Основные характеристики:
- Длина адреса: 128 бит (в 4 раза длиннее IPv4).

- Запись: 8 групп по 4 шестнадцатеричные цифры, разделенных двоеточиями (:).
    Пример: 2001:0db8:85a3:0000:0000:8a2e:0370:7334

# Таблица маршрутизации

Таблица маршрутизации — это «карта», на основе которой операционная система или маршрутизатор принимает решение: через какой интерфейс и на какой шлюз (Gateway) отправить IP-пакет.

## Чтение вывода ip route и ip -6 route

Основной инструмент управления маршрутизацией в современном Linux — утилита iproute2.

Вывод ip route (IPv4)
Типичный вывод команды ip route:

```
default via 192.168.1.1 dev eth0 proto dhcp metric 100 
10.0.0.0/24 via 192.168.1.254 dev eth0 proto static metric 10 
192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50 metric 100
```

Вывод ip -6 route (IPv6)
Типичный вывод команды ip -6 route:

```
::1 dev lo proto kernel metric 256 pref medium
2001:db8:1::/64 dev eth0 proto kernel metric 256 pref medium
fe80::/64 dev eth0 proto kernel metric 256 pref medium
default via fe80::1 dev eth0 proto ra metric 1024 pref medium
```

| Поле / Элемент | Значение | Пример |
|---|---|---|
| Назначение | Целевая сеть/маска или default (0.0.0.0/0) | 10.0.0.0/24, default |
| via <IP> | IP-адрес следующего прыжка (Next-Hop / Gateway) | via 192.168.1.1 |
| dev <iface> | Сетевой интерфейс, через который уходит пакет | dev eth0 |
| proto <origin> | Источник происхождения маршрута | proto kernel, proto static, proto dhcp |
| scope <scope> | Область видимости маршрута (global, link, host) | scope link (доступен прямо на проводе) |
| src <IP> | IP-адрес источника по умолчанию при отправке пакетов | src 192.168.1.50 |
| metric <N> | Числовое значение стоимости/приоритета маршрута | metric 100 |

## Типы маршрутов: Connected, Static, Default

### Connected Routes (Прямо подключенные сети)

Автоматически создаются ядром Linux (proto kernel), когда сетевому интерфейсу назначается IP-адрес и маска.

Указывают, что целевая подсеть находится прямо на физическом/виртуальном проводе данного интерфейса (шлюз via не нужен).

При назначении адреса 192.168.1.50/24 на eth0 ядро автоматически добавляет:

192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.50


### Static Routes (Статические маршруты)

Добавляются вручную системным администратором (ip route add ...) или скриптами конфигурации сети (netplan, systemd-networkd, NetworkManager).

Указывают явный путь к сетям, которые находятся за пределами локального сегмента.

```
ip route add 10.50.0.0/16 via 192.168.1.254 dev eth0
```

### Metric (Метрика)

Если для одной и той же подсети с одинаковой маской существует несколько маршрутов, система выбирает маршрут с наименьшим значением метрики (Metric / Cost).

default via 192.168.1.1 dev eth0 metric 100 (Ethernet)default via 192.168.8.1 dev wlan0 metric 600 (Wi-Fi)Весь интернет-трафик пойдет через eth0, так как $100 < 600$. Если кабель eth0 выдернуть, маршрут с метрикой 100 исчезнет, и система автоматически переключится на Wi-Fi.

### Administrative Distance / Preference (Протокольное предпочтение)

В профессиональных маршрутизаторах (Cisco, MikroTik, FRRouting в Linux) при наличии маршрутов из разных источников (например, Static vs OSPF vs BGP) приоритет определяется административным расстоянием (AD). Чем меньше AD, тем выше доверие источнику:

## Определение выбранного маршрута: ip route get

по которому на самом деле пойдет пакет.

## Маршрут по умолчанию

Маршрутизатор должен знать ообо всех существующих сетях или подсетях. На практике это невозможно

Маршрутизатор по умолчанию (шлюз, default router, getaway) - маршуртизатор на который отправялются пакеты
из неизвестных сетей

```
% netstat -rn

Destination        Gateway            Flags               Netif Expire
default            192.168.0.1        UGScg                 en0   
```

«Маршрут последней надежды». Если IP-адрес назначения пакета не совпал ни с одним другим маршрутом в таблице, пакет отправляется на Default Gateway.

## Выбор маршрута: Longest Prefix Match, Metric, Preference

### Longest Prefix Match (LPM / Принцип наиболее длинного префикса)

Главное правило маршрутизации: Из всех совпавших маршрутов выбирается тот,
у которого самая длинная маска подсети (наиболее специфичный маршрут).

Пример таблицы:

0.0.0.0/0 via 192.168.1.1 (маска /0)

10.0.0.0/8 via 192.168.1.254 (маска /8)

10.20.0.0/16 via 192.168.1.253 (маска /16)

10.20.30.0/24 via 192.168.1.252 (маска /24)

Пакет уходит на 10.20.30.45: Совпадают маршруты 1, 2, 3 и 4. Пакет пойдет через Маршрут 4 (маска /24 — самая длинная).

Пакет уходит на 10.20.99.5: Совпадают маршруты 1, 2 и 3. Пакет пойдет через Маршрут 3 (маска /16).

Пакет уходит на 8.8.8.8: Совпадает только маршрут 1 (default).

# Фрагментация

Фрагментация - разделение пакета на несколько частей (фрагментов) для передачи по сети с маленьким MTU

## Флаги

Размер поля флаги - 3 бита

Значение полей
- Первый бит не используется
- DF (Don't Fragment) - не фрагментировать
- MF (More Fragments) - есть еще фрагменты

## Смещение фрагмента

IP не гарантирует доставку пакетов и сохранение их порядка следования, поэтому фрагменты одного пакета могут прийти в разном порядке.

Fragment Offset показывает положение каждого фрагмента относительно начала исходного пакета и позволяет правильно собрать его обратно.

Допустим, исходный пакет содержит 4000 байт данных.

Фрагмент 1: байты 0–1399
Фрагмент 2: байты 1400–2799
Фрагмент 3: байты 2800–3999


Фрагмент 1:
0 / 8 = 0

Фрагмент 2:
1400 / 8 = 175

Фрагмент 3:
2800 / 8 = 350

Фрагмент       Fragment Offset
№1                0
№2              175
№3              350

## Сборка пакета

**Сборка (reassembly)** — процесс объединения фрагментов обратно в исходный IP-пакет.

Например, исходный пакет разделили:

```text
Фрагмент 1 → Offset = 0
Фрагмент 2 → Offset = 175
Фрагмент 3 → Offset = 350
```

Фрагменты могут прийти **в разном порядке**:

```text
2 → 1 → 3
```

Получатель использует:

* **Identification** — определяет, что фрагменты относятся к одному исходному пакету.
* **Fragment Offset** — определяет положение каждого фрагмента.
* **MF (More Fragments)** — показывает, что после данного фрагмента есть ещё фрагменты.

После этого данные объединяются обратно:

```text
Фрагмент 1 + Фрагмент 2 + Фрагмент 3
                 ↓
          Исходный пакет
```

Если какого-либо фрагмента не хватает, исходный пакет собрать нельзя.

# Управляющие протоколы сетевого взаимодействия

Используются для не для передачи данных а для обеспечения работы в сети

## Протокол DHCP

**DHCP (Dynamic Host Configuration Protocol)** — протокол динамической настройки сетевых параметров устройства.

Позволяет автоматически получить:

* **IP-адрес**
* **маску подсети**
* **шлюз по умолчанию**
* **адреса DNS-серверов**
* срок действия выданного адреса (**lease**)

Без DHCP сетевые параметры пришлось бы настраивать вручную.

Пример:

```text
Компьютер → DHCP-сервер:
«Мне нужны сетевые настройки»

DHCP-сервер → Компьютер:
IP:      192.168.0.15
Маска:   255.255.255.0
Шлюз:    192.168.0.1
DNS:     8.8.8.8
```

---

## Протокол ARP

**ARP (Address Resolution Protocol)** — протокол разрешения IPv4-адресов в **MAC-адреса**.

Он нужен, когда устройство знает IP получателя в локальной сети, но не знает его MAC-адрес.

Например:

```text
IP: 192.168.0.1
        ↓
MAC: e8:1b:69:1b:c8:6e
```

Компьютер отправляет ARP-запрос:

> «Кто имеет IP 192.168.0.1?»

Устройство с этим IP отвечает своим MAC-адресом.

Полученная информация сохраняется в **ARP-кэше**, чтобы не выполнять запрос каждый раз.

ARP работает только для устройств, находящихся в **локальной сети**. Для удалённой сети компьютер узнаёт MAC-адрес **шлюза**, а не конечного сервера.

---

## Протокол ICMP

**ICMP (Internet Control Message Protocol)** — протокол управляющих сообщений сетевого уровня.

Он используется для передачи информации об ошибках и состоянии сети.

### Сообщения об ошибках

Например:

* **Destination Unreachable** — получатель или сеть недоступны.
* **Time Exceeded** — истёк TTL пакета.
* **Fragmentation Needed** — пакет слишком большой для следующего канала и требуется фрагментация, если она разрешена; при запрете фрагментации пакет не может быть передан.

### Тестирование сети

#### `ping`

Использует ICMP-сообщения **Echo Request** и **Echo Reply**.

```text
Компьютер → Echo Request → Сервер
Компьютер ← Echo Reply   ← Сервер
```

Позволяет проверить:

* доступность узла;
* время прохождения сообщения (**RTT**);
* наличие потерь.

#### `traceroute`

Позволяет определить, **через какие маршрутизаторы проходит пакет** до получателя.

Принцип основан на изменении значения **TTL**:

```text
TTL = 1 → отвечает первый маршрутизатор
TTL = 2 → отвечает второй
TTL = 3 → отвечает третий
...
```

Так постепенно определяется маршрут до конечного узла.


# Соседи и канальный уровень

Маршрутизация на L3-уровне (IP) отвечает за логический поиск пути между сетями. Однако для реальной передачи кадров через физический провод или Wi-Fi на L2-уровне (Ethernet) необходимы физические MAC-адреса устройств.

## Протоколы разрешения адресов: ARP (IPv4) и Neighbor Discovery (IPv6)

Протоколы канального уровня связывают IP-адреса с MAC-адресами конкретных сетевых интерфейсов.

### ARP (Address Resolution Protocol) — IPv4

Служит для преобразования IPv4-адреса в MAC-адрес в пределах одного L2-домена.

Принцип работы:

1. ARP Request: Если узел не знает MAC-адрес целевого IP, он отправляет широковещательный запрос (Broadcast) на FF:FF:FF:FF:FF:FF: «У кого IP 192.168.1.1? Сообщите 192.168.1.50».

2. ARP Reply: Владелец IP-адреса отвечает одноадресным пакетом (Unicast): «У меня IP 192.168.1.1, мой MAC — AA:BB:CC:DD:EE:FF».

3. Полученный ответ сохраняется в локальном ARP-кэше.

### Neighbor Discovery Protocol (NDP) — IPv6

В IPv6 нет broadcast-трафика. Его функции выполняет протокол NDP, работающий поверх ICMPv6.

Заменяет ARP за счет двух сообщений ICMPv6:

1. Neighbor Solicitation (NS, тип 135): Запрос адреса. Отправляется не на общий broadcast, а на специальный Solicited-Node Multicast адрес (группа ff02::1:ffXX:XXXX), что снижает нагрузку на другие узлы сети.

2. Neighbor Advertisement (NA, тип 136): Ответ с указанием MAC-адреса (Unicast).

Дополнительные функции NDP:

- Router Advertisement (RA) / Router Solicitation (RS): Автоматическое обнаружение роутеров и автонастройка IP-адресов без DHCP (SLAAC).

- DAD (Duplicate Address Detection): Проверка уникальности адреса перед назначением.

## Управление таблицей соседей

Состояние связей L3 -> L2 на Linux-узле проверяется с помощью утилиты iproute2.

### Чтение таблицы соседей

```
# Просмотр IPv4 (ARP) и IPv6 (NDP) соседей
$ ip neigh

# Только IPv6 соседи
$ ip -6 neigh
```

## Команды администрирования ARP/NDP

```
# Ручное добавление статической ARP-записи
$ sudo ip neigh add 192.168.1.10 lladdr 00:11:22:33:44:55 dev eth0

# Удаление записи из кэша
$ sudo ip neigh del 192.168.1.10 dev eth0

# Очистка всего ARP/NDP кэша (Flush)
$ sudo ip neigh flush dev eth0
```

## Роль MAC-адреса и Next Hop при передаче пакета

Критически важно понимать различие между адресацией на L3 и L2 при прохождении пакета через маршрутизатор.

Главное правило:

IP-адреса (Источник и Назначение) остаются неизменными на всем пути следования пакета.

MAC-адреса (Источник и Назначение) перезаписываются на каждом L3-прыжке (Hop)!

## Пошаговый путь пакета от Хоста A к Хосту B:

Принятие решения на L3 (Маршрутизация):

1. Хост A видит, что целевой IP 10.0.0.100 находится вне его локальной сети (192.168.1.0/24). По таблице маршрутизации определяется Next Hop (Шлюз) — 192.168.1.1.

2. Формирование L2-кадра (Хост A $\rightarrow$ R1):
  - IP Header: Source IP = 192.168.1.50 | Dest IP = 10.0.0.100
  - Ethernet Header: Source MAC = AA:AA:AA:AA:AA:AA | Dest MAC = MAC-адрес Шлюза (R1) (R1:R1:R1:R1)

3. Обработка на Роутере (R1):  
  Роутер снимает L2-заголовок, видит свой MAC-адрес назначения, принимает пакет, снижает TTL на 1 и ищет 10.0.0.100 в своей таблице маршрутизации.

4. Формирование L2-кадра (R1 $\rightarrow$ Хост B):
  - IP Header: Source IP = 192.168.1.50 | Dest IP = 10.0.0.100 (IP-адреса не изменились!)
  - Ethernet Header: Source MAC = MAC2 Роутера (R2:R2:R2:R2) | Dest MAC = MAC-адрес Хоста B (BB:BB:BB:BB:BB:BB)

## Диагностика проблем: Duplicate IP и недоступность шлюза

### Конфликт IP-адресов (Duplicate IP)

Происходит, когда два устройства в одном L2-сегменте настраиваются с одинаковым IP-адресом. Это приводит к нестабильному соединению, так как коммутаторы и ARP-таблицы начинают «флудить» и постоянно перезаписывать MAC-адрес для этого IP (ARP poisoning / flapping).

Инструменты диагностики:
    
- arping: Отправляет ARP-запросы целевому IP. Позволяет мгновенно обнаружить наличие двух MAC-адресов на один IP.
- Логи ядра Linux (dmesg): При обнаружении дубликата IPv4/IPv6 Linux выведет сообщение в системный лог

### Недоступность шлюза (Gateway Unreachable)

Ситуация, когда маршрут по умолчанию установлен, но трафик наружу не уходит.

Команды для диагностики:

1. Проверить наличие ARP-записи шлюза:
    ```
    ip neigh show 192.168.1.1
    ```
2. Проверить прохождение ARP через arping:
    ```
    sudo arping -I eth0 192.168.1.1
    ```
3. Отследить путь пакета:
   ```
   traceroute -n 8.8.8.8
   ```

# Маршрутизация в Linux

Превращение Linux-узла в полноценный маршрутизатор требует умения управлять сетевым стеком в режиме реального времени, включать пересылку IP-пакетов на уровне ядра и сохранять настройки при перезагрузке.


Этапы маршрутизации:
- изучение сети
- Продвижение (forwarding) пакетов на маршрутизации


## Оперативное управление сетевым стеком через iproute2

Команды утилиты ip изменяют конфигурацию немедленно в оперативной памяти, но сбрасываются после перезагрузки системы.

### Управление интерфейсами и IP-адресами

```
# Включить / выключить сетевой интерфейс
$ sudo ip link set dev eth1 up
$ sudo ip link set dev eth1 down

# Добавить IP-адрес на интерфейс
$ sudo ip addr add 192.168.10.1/24 dev eth1
$ sudo ip -6 addr add 2001:db8:10::1/64 dev eth1

# Удалить IP-адрес
$ sudo ip addr del 192.168.10.1/24 dev eth1

# Посмотреть текущие адреса и состояние
$ ip -brief addr show
```

### Управление таблицей маршрутизации

```
# Добавить статический маршрут к подсети через шлюз
$ sudo ip route add 10.50.0.0/16 via 192.168.10.254 dev eth1

# Добавить маршрут по умолчанию (Default Gateway)
$ sudo ip route add default via 192.168.1.1 dev eth0

# Удалить маршрут
$ sudo ip route del 10.50.0.0/16

# Заменить существующий маршрут (например, сменить метрику или шлюз)
$ sudo ip route change default via 192.168.1.2 dev eth0 metric 10
```

## Включение IP Forwarding (Пересылки пакетов)

По умолчанию Linux работает в режиме Host (конечный узел) и отбрасывает транзитные пакеты, адресованные не ему. Чтобы превратить систему в Router, необходимо активировать IP Forwarding в ядре.

### Временное включение (до перезагрузки)

```
# Включить IPv4 forwarding
$ sudo sysctl -w net.ipv4.ip_forward=1

# Включить IPv6 forwarding
$ sudo sysctl -w net.ipv6.conf.all.forwarding=1
```

### Постоянное включение (персистентное)

```
$ sudo nano /etc/sysctl.d/99-ip-forward.conf
```

```
net.ipv4.ip_forward = 1
net.ipv6.conf.all.forwarding = 1
```

```
sudo sysctl --system
```

## Настройка Linux как маршрутизатора между двумя подсетями

1. Включите IP Forwarding
    ```
    $ sudo sysctl -w net.ipv4.ip_forward=1
    ```

2. Настройте IP-адреса на интерфейсах роутера
    ```
    $ sudo ip addr add 192.168.1.254/24 dev eth0
    $ sudo ip addr add 10.0.10.254/24 dev eth1
    $ sudo ip link set dev eth0 up
    $ sudo ip link set dev eth1 up
   ```

3. Проверьте и настройте Firewall (iptables / nftables)

    ```
    # Разрешить транзит между eth0 и eth1
    $ sudo iptables -A FORWARD -i eth0 -o eth1 -j ACCEPT
    $ sudo iptables -A FORWARD -i eth1 -o eth0 -m state --state RELATED,ESTABLISHED -j ACCEPT
    ```

4. Настройте хосты в подсетях

Убедитесь, что на клиентах указаны правильные Default Gateway:

- Хост в Сети 1 (192.168.1.10): Default Gateway = 192.168.1.254

- Хост в Сети 2 (10.0.10.5): Default Gateway = 10.0.10.254

## Сохранение конфигурации после перезагрузки

Различные дистрибутивы Linux используют разные сетевые менеджеры для сохранения настроек.

## Netplan (Ubuntu Server)

Конфигурация задается в YAML-файлах в директории /etc/netplan/ (например, /etc/netplan/01-netcfg.yaml).

```
network:
  version: 2
  renderer: networkd
  ethernets:
    eth0:
      addresses:
        - 192.168.1.254/24
      routes:
        - to: default
          via: 192.168.1.1
    eth1:
      addresses:
        - 10.0.10.254/24
      routes:
        - to: 10.50.0.0/16
          via: 10.0.10.1
```

```
$ sudo netplan apply
```

## NetworkManager / nmcli (RHEL / Rocky Linux / CentOS / Fedora)


```
# Настройка static IP
$ sudo nmcli con mod eth0 ipv4.addresses 192.168.1.254/24
$ sudo nmcli con mod eth0 ipv4.gateway 192.168.1.1
$ sudo nmcli con mod eth0 ipv4.method manual

# Добавление статического маршрута
$ sudo nmcli con mod eth1 +ipv4.routes "10.50.0.0/16 10.0.10.1"

# Переподключение интерфейса для применения
$ sudo nmcli con up eth0
```

# Статическая маршрутизация


## Настройка статических маршрутов на нескольких узлах

Рассмотрим базовую топологию из трех узлов: Клиент (Host A), Маршрутизатор (Router R1) и Сервер (Host B).

```
[ Host A ] ────────── [ Router R1 ] ────────── [ Host B ]
192.168.1.10/24     192.168.1.1   10.0.0.1      10.0.0.5/24
                     (eth0)        (eth1)
```

1. Хост A (192.168.1.10):
   Указываем роутер R1 в качестве шлюза по умолчанию для выходящего трафика.
    ```
   sudo ip route add default via 192.168.1.1 dev eth0
   ```
2. Маршрутизатор R1 (с включенным ip_forward=1):
   Имеет два напрямую подключенных (connected) интерфейса. Ему не нужно настраивать маршруты к сетям 192.168.1.0/24 и 10.0.0.0/24, они создаются автоматически.
3. Хост B (10.0.0.5):
   Чтобы отвечать на запросы от Хоста A, узел должен знать, где находится сеть 192.168.1.0/24.
    ```
    # Точечный маршрут к конкретной сети
    $ sudo ip route add 192.168.1.0/24 via 10.0.0.1 dev eth0
    
    # Или единый Default Gateway
    $ sudo ip route add default via 10.0.0.1 dev eth0
    ```

## Резервный маршрут (Floating Static Route / Метрики)

Когда между двумя точками есть основной (быстрый) и резервный (медленный/дорогой) каналы, используется механизм Floating Static Route. Резервный маршрут активируется автоматически, только если основной физически исчезает из таблицы маршрутизации.

```
                       ┌─── [ Основной ISP1 (100 Мбит/с) ] ───┐
                       │      Metric 10                       │
 [ Офисный Роутер ] ───┤                                      ├─── [ Интернет / ЦОД ]
                       │      Metric 100                      │
                       └─── [ Резервный ISP2 (LTE 10 Мбит/с) ] ┘
```

Настройка через iproute2:

```
# 1. Основной маршрут через провайдера ISP1 (приоритетный)
$ sudo ip route add default via 192.168.1.1 dev eth0 metric 10

# 2. Резервный (плавающий) маршрут через провайдера ISP2
$ sudo ip route add default via 10.100.0.1 dev wlan0 metric 100
```

## Симметричность и асимметричность маршрутизации

Симметричность пути — важнейший фактор стабильности работы сети и сетевых экранов (Firewall / NAT).

- Симметричный путь: Прямой пакет (A -> B) и обратный ответ (B <- A) проходят через один и тот же набор маршрутизаторов.

- Асимметричный путь: Прямой и обратный пакеты идут по разным физическим или логическим маршрутам.

## Ограничения статической маршрутизации

Несмотря на простоту и нулевую нагрузку на процессор, статическая маршрутизация непригодна для крупных или динамически меняющихся сетей.

- Плохая масштабируемость
- Отсутствие адаптивности
- Человеческий фактор
- Сложность балансировки


# Таблицы маршрутизации и RPDB

По умолчанию Linux использует Routing Policy Database (RPDB) для выбора маршрута. Правила RPDB проверяются последовательно в соответствии с их приоритетом: от меньшего значения к большему.

## Просмотр правил RPDB

Для просмотра существующих правил используется команда:

```bash
ip rule show
```

## Кастомные таблицы маршрутизации

Помимо стандартных таблиц `local`, `main` и `default`, в Linux можно создавать собственные таблицы маршрутизации.

Имена и идентификаторы таблиц указываются в файле:

```text
/etc/iproute2/rt_tables
```

Например:

```text
200 ISP2
```

После этого таблицу можно использовать по номеру или имени.

## Просмотр таблицы

По номеру:

```bash
ip route show table 200
```

По имени:

```bash
ip route show table ISP2
```

# Создание правил ip rule

Правила `ip rule` позволяют выбирать таблицу маршрутизации в зависимости от различных параметров пакета.

## Маршрутизация по IP-адресу источника

Можно направить весь трафик от определённого IP-адреса в отдельную таблицу:

```bash
sudo ip rule add from 192.168.10.50 lookup 200 priority 100
```

В данном случае трафик с адреса `192.168.10.50` будет обрабатываться с использованием таблицы маршрутизации `200`.

## Маршрутизация по fwmark

Другой вариант — использовать специальную метку пакета `fwmark`.

Например:

```bash
sudo ip rule add fwmark 0x1 lookup 200 priority 101
```

Пакеты с меткой `0x1` будут направляться для поиска маршрута в таблицу `200`.

Такие метки могут устанавливать `nftables` или `iptables`.

# Policy Routing для узла с несколькими интерфейсами

Policy Routing может использоваться на узлах с несколькими сетевыми интерфейсами.

Например, компьютер может иметь два интерфейса:

* `eth1` с адресом `192.168.1.10`;
* `eth2` с адресом `10.0.0.10`.

Для каждого интерфейса можно создать отдельную таблицу маршрутизации.

## Создание маршрутов по умолчанию

Для первого интерфейса:

```bash
sudo ip route add default via 192.168.1.1 dev eth1 table 100
```

Для второго интерфейса:

```bash
sudo ip route add default via 10.0.0.1 dev eth2 table 200
```

## Создание правил

Трафик с адреса `192.168.1.10` можно направить в таблицу `100`:

```bash
sudo ip rule add from 192.168.1.10 lookup 100
```

Трафик с адреса `10.0.0.10` можно направить в таблицу `200`:

```bash
sudo ip rule add from 10.0.0.10 lookup 200
```

Такой подход позволяет выбирать маршрут в зависимости от адреса источника.

# Взаимодействие Policy Routing, Firewall Marks и NAT

При обработке пакета в Linux сначала может выполняться маркировка пакета, затем принимается решение о маршрутизации, после чего выполняется NAT.

Упрощённая последовательность выглядит следующим образом:

```text
PREROUTING
    |
    v
Routing Decision
    |
    v
POSTROUTING
```

## Маркировка пакета

В цепочке `PREROUTING` с помощью `nftables` или `iptables` пакету можно назначить специальную метку.

Например, в `nftables` используется значение `mark`.

В `iptables` для установки метки может использоваться:

```bash
-j MARK --set-mark 1
```

## Выбор маршрута

После установки метки ядро принимает решение о маршрутизации.

Если существует правило:

```bash
sudo ip rule add fwmark 0x1 lookup 200
```

то пакет с меткой `0x1` будет использовать таблицу маршрутизации `200`.

## NAT

После выбора маршрута пакет проходит через `POSTROUTING`, где может выполняться преобразование сетевых адресов.

Например, можно использовать SNAT или Masquerade.

При Masquerade исходный IP-адрес пакета заменяется на IP-адрес выбранного выходного интерфейса.

Таким образом, общая схема обработки может быть представлена следующим образом:

```text
Получение пакета
      |
      v
PREROUTING
      |
      v
Установка fwmark
      |
      v
RPDB и ip rule
      |
      v
Выбор таблицы маршрутизации
      |
      v
Выбор выходного интерфейса
      |
      v
POSTROUTING
      |
      v
SNAT или Masquerade
```

# Динамическая маршрутизация

## Различия Distance-Vector и Link-State протоколов

### Distance-Vector

К протоколам Distance-Vector относятся RIP и EIGRP.

* Принцип работы: маршрутизаторы обмениваются информацией о маршрутах с соседними узлами.
* Метрика: количество хопов для RIP или составная метрика для EIGRP.
* Особенности:

   * относительно небольшие требования к ресурсам;
   * возможна медленная сходимость;
   * существует риск образования маршрутизационных петель.

### Link-State

К протоколам Link-State относятся OSPF и IS-IS.

* Принцип работы: маршрутизатор получает информацию о состоянии соединений и формирует представление о топологии сети.
* Алгоритм: для расчёта кратчайших путей используется алгоритм Дейкстры SPF.
* Особенности:

   * быстрая сходимость;
   * хорошая масштабируемость;
   * более высокие требования к CPU и памяти по сравнению с простыми Distance-Vector протоколами.

## Назначение OSPF и BGP

### OSPF

OSPF (Open Shortest Path First) — протокол динамической маршрутизации, предназначенный для работы внутри автономной системы.

* Тип: IGP (Interior Gateway Protocol).
* Область применения:

   * корпоративные сети;
   * сети дата-центров;
   * другие внутренние IP-сети.
* Метрика: стоимость (Cost), которая обычно связана с пропускной способностью интерфейса.
* Для построения таблицы маршрутизации используется информация о топологии сети.

### BGP

BGP (Border Gateway Protocol) используется для обмена маршрутами между автономными системами.

* Тип: EGP (Exterior Gateway Protocol), протокол типа Path-Vector.
* Область применения:

   * Интернет;
   * взаимодействие сетей разных организаций;
   * подключение к интернет-провайдерам.
* Выбор маршрута осуществляется на основе атрибутов пути и настроенных политик.

К основным атрибутам BGP относятся:

* AS-Path;
* Local Preference;
* MED.

В отличие от OSPF, BGP предназначен прежде всего для управления маршрутизацией между автономными системами.

## Развертывание FRRouting

FRRouting (FRR) — открытый программный стек динамической маршрутизации для Linux. Он поддерживает такие протоколы, как OSPF и BGP.

### Установка

Для установки FRRouting используется команда:

```bash
sudo apt update && sudo apt install -y frr
```

### Включение демонов

В файле `/etc/frr/daemons` можно включить необходимые протоколы.

Например:

```text
ospfd=yes
bgpd=yes
```

После изменения конфигурации необходимо перезапустить службу:

```bash
sudo systemctl restart frr
```

## Настройка соседства OSPF и обмен маршрутами

Для настройки OSPF используется консоль FRR `vtysh`.

### Вход в консоль

```bash
sudo vtysh
```

### Настройка OSPF на Router1

Для настройки OSPF можно использовать следующую конфигурацию:

```text
configure terminal
router ospf
  ospf router-id 1.1.1.1
  network 192.168.0.0/24 area 0
  network 192.168.10.0/24 area 0
exit
```

Здесь:

* `router ospf` включает режим настройки OSPF;
* `ospf router-id 1.1.1.1` задаёт идентификатор маршрутизатора;
* `network 192.168.0.0/24 area 0` добавляет сеть в область OSPF 0;
* `network 192.168.10.0/24 area 0` добавляет вторую сеть в область OSPF 0.

### Проверка состояния OSPF

Для просмотра соседей используется:

```text
show ip ospf neighbor
```

Для просмотра маршрутов OSPF:

```text
show ip ospf route
```

Для просмотра общей таблицы маршрутизации:

```text
show ip route
```

Эти команды позволяют проверить установление соседства между маршрутизаторами и наличие маршрутов, полученных с помощью OSPF.


# Отказоустойчивость

## Переключение на резервный маршрут

Для обеспечения отказоустойчивости можно использовать несколько статических маршрутов к одной сети с разными метриками.

Основной маршрут имеет меньшую метрику и используется в обычных условиях. Резервный маршрут имеет большую метрику и используется при недоступности основного маршрута.

Например:

```bash
sudo ip route add 10.0.2.0/24 via 192.168.0.2 dev eth1 metric 10
sudo ip route add 10.0.2.0/24 via 192.168.100.2 dev eth2 metric 100
```

В данном случае:

* маршрут через `192.168.0.2` имеет метрику `10`;
* маршрут через `192.168.100.2` имеет метрику `100`;
* при наличии обоих маршрутов предпочтение отдаётся маршруту с меньшей метрикой.

Для настоящего резервирования пути должны быть независимыми. Например, резервный маршрут может использовать другой интерфейс или другой следующий маршрутизатор.

## Equal-Cost Multi-Path Routing

ECMP (Equal-Cost Multi-Path) позволяет использовать несколько маршрутов одинаковой стоимости одновременно.

Вместо выбора одного основного и одного резервного маршрута система может распределять трафик между несколькими доступными путями.

Например:

```bash
sudo ip route add 10.0.2.0/24 \
    nexthop via 192.168.0.2 dev eth1 weight 1 \
    nexthop via 192.168.100.2 dev eth2 weight 1
```

В данном случае для сети `10.0.2.0/24` используются два следующих маршрутизатора с одинаковым весом.

Распределение трафика обычно выполняется на основе хэширования параметров соединения. Это позволяет сохранять пакеты одной сессии на одном пути и уменьшать вероятность их переупорядочивания.

## Контроль доступности следующего узла

Одной из проблем статической маршрутизации является невозможность автоматически определить некоторые виды отказов.

Например, физический интерфейс может оставаться в состоянии `UP`, хотя следующий маршрутизатор или промежуточное сетевое оборудование уже недоступно.

Для контроля доступности следующего узла используются следующие механизмы:

* BFD (Bidirectional Forwarding Detection);
* периодические ICMP-проверки;
* IP SLA и аналогичные механизмы;
* специальные скрипты и службы мониторинга.

BFD предназначен для быстрого обнаружения отказов сетевого пути и может использоваться совместно с FRR и протоколами динамической маршрутизации.

Проверка с помощью ICMP может выполнять периодические запросы к следующему маршрутизатору. Если узел перестаёт отвечать, специальный механизм может изменить или удалить маршрут.

## Асимметричная маршрутизация и Reverse Path Filtering

Асимметричная маршрутизация возникает, когда пакет в прямом и обратном направлениях проходит через разные маршруты.

Например:

```text
A → R1 → R2 → B
A ← R3 ← R2 ← B
```

В этом случае прямой и обратный трафик используют разные пути.

Асимметричная маршрутизация может создавать проблемы для stateful firewall, поскольку межсетевой экран отслеживает состояние соединений и ожидает увидеть связанные пакеты через соответствующие интерфейсы.

## Reverse Path Filtering

`rp_filter` — механизм Linux, который используется для защиты от IP-спуфинга.

При получении пакета ядро проверяет маршрут до его исходного IP-адреса и определяет, соответствует ли входящий интерфейс ожидаемому обратному пути.

Основные режимы:

* `0` — проверка отключена;
* `1` — строгий режим. Пакет принимается только в том случае, если обратный маршрут указывает на тот же интерфейс;
* `2` — свободный режим. Пакет принимается, если исходный адрес доступен через любой интерфейс.

Для сетей с ECMP, Policy Routing или асимметричной маршрутизацией может потребоваться использование свободного режима.

## Настройка rp_filter

Для включения свободного режима можно использовать:

```bash
sudo sysctl -w net.ipv4.conf.all.rp_filter=2
sudo sysctl -w net.ipv4.conf.eth0.rp_filter=2
```

После изменения параметров ядро будет использовать режим `Loose` для соответствующих интерфейсов.


# Диагностика

Для поиска и устранения проблем в сети используются различные инструменты диагностики.

## Основные инструменты

* `ping` — проверка доступности узла и базового сетевого соединения.
* `tracepath` — определение пути прохождения пакетов и проверка Path MTU.
* `traceroute` — определение маршрута от источника до назначения.
* `mtr` — сочетает функции `ping` и `traceroute` и позволяет наблюдать состояние маршрута в динамике.

## Анализ ICMP и Path MTU Discovery

ICMP-сообщения используются для передачи информации об ошибках и состоянии сетевого соединения.

При диагностике необходимо учитывать сообщения, связанные с недоступностью узла, превышением времени ожидания и изменением максимального размера передаваемого пакета.

Path MTU Discovery позволяет определить максимальный размер IP-пакета, который может пройти по всему маршруту без фрагментации.

## Захват сетевого трафика

Для анализа сетевого трафика можно использовать `tcpdump`.

Например:

```bash
sudo tcpdump -i eth0
```

Для фильтрации ICMP:

```bash
sudo tcpdump -i eth0 icmp
```

Для просмотра ARP:

```bash
sudo tcpdump -i eth0 arp
```

Захват трафика позволяет определить, проходят ли пакеты через нужный интерфейс и возвращаются ли ответы.

## Определение типа ошибки

При диагностике сетевых проблем необходимо определить уровень, на котором возникает ошибка.

Основные варианты:

* DNS — имя узла не преобразуется в IP-адрес;
* маршрутизация — отсутствует или неправильно настроен маршрут;
* firewall — пакеты блокируются правилами фильтрации;
* транспортный уровень — проблемы с TCP или UDP;
* приложение — сеть работает, но само приложение не отвечает.

Для последовательной диагностики сначала проверяют доступность IP-адреса с помощью `ping`, затем анализируют маршрут с помощью `tracepath`, `traceroute` или `mtr`, после чего при необходимости исследуют сетевой трафик с помощью `tcpdump`.

# Эксплуатация и безопасность

## Документирование сети

Необходимо документировать используемые сети, IP-адреса, шлюзы и маршруты.

Для каждого маршрута рекомендуется указывать:

* сеть назначения;
* шлюз или следующий маршрутизатор;
* используемый интерфейс;
* источник маршрута;
* назначение маршрута.

Это упрощает диагностику и последующее изменение конфигурации.

## Ограничение маршрутизируемого трафика

Маршрутизаторы должны пропускать только необходимый трафик между сетями.

Для ограничения доступа можно использовать межсетевой экран, например `nftables`.

Правила firewall позволяют контролировать:

* источники и назначения;
* используемые протоколы;
* TCP и UDP-порты;
* направления трафика.

## Предотвращение утечек маршрутов

Необходимо избегать случайной передачи маршрутов между сетями.

Особое внимание следует уделять слишком широким префиксам, например `0.0.0.0/0`, которые могут привести к передаче большого количества трафика через один маршрутизатор.

Перед добавлением маршрута необходимо проверить:

* сеть назначения;
* следующий узел;
* маску сети;
* приоритет маршрута;
* доступность следующего узла.

## Проверка и мониторинг

Для контроля состояния сети необходимо подготовить команды диагностики.

Например:

```bash
ip addr
ip route
ip rule
ping 192.168.10.1
traceroute 192.168.30.10
```

При необходимости для анализа трафика используется:

```bash
sudo tcpdump -i eth0
```

Регулярная проверка маршрутов и доступности узлов позволяет своевременно обнаруживать ошибки конфигурации.

## Сценарий отката

Перед изменением маршрутизации необходимо сохранить текущую конфигурацию.

При возникновении проблем следует иметь возможность удалить добавленные маршруты и вернуть предыдущую конфигурацию.

Например:

```bash
sudo ip route del 10.0.2.0/24
```

После изменения конфигурации необходимо повторно проверить таблицу маршрутизации:

```bash
ip route
```

и доступность узлов:

```bash
ping <IP-адрес>
```
